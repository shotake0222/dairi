# テキストの会話から、ロボットの行動まで

最終更新: 2026-09-19

## 0. 問い

わけたまが持っているのは、**文字の会話だけ**。カメラも加速度計も付いていない。
そこから、体を持ったロボットの行動をどうやって決めるのか。

答えは「LLMに毎回考えさせる」ではない。それだと遅く、高く、ネットが切れた瞬間に止まり、
**同じ状況で同じ子が毎回違う動きをする**。人格として成立しない。

代わりに、**言葉を数値に落としてから、機器へ渡す**。
翻訳はサーバー側で一度だけ行い、機器はその数値を読んで動く。

```
会話（テキスト）
   ↓ ① 1ターンごと
性格 6軸（0〜100）
   ↓ ② 数ターンごと
価値観 8軸（0〜100）＋ 覚え書き
   ↓ ③ 本人の申告で上書き
確定した価値観
   ↓ ④ 変換（ここが肝）
身体パラメータ ＋ 方針コード
   ↓ ⑤ 最小化
数百バイトのJSON
   ↓ ⑥ 機器側
イベント → 動作
```

## 1. 会話 → 性格6軸

**どこ**: `src/ai/signalExtractor.ts` → `src/ai/personality.ts`

1往復ごとに、発言から信号を拾って6軸を**少しずつ**動かす。

| 軸 | 上がる合図の例 |
|---|---|
| 温かさ | ねぎらい、心配、感謝 |
| 好奇心 | 質問、「なんで」、知らない話題への食いつき |
| 陽気さ | 笑い、感嘆、テンポの速い返し |
| 慎重さ | 確認、条件付け、「一応」「念のため」 |
| 自立心 | 自分で決める言い方、相談しない |
| ユーモア | 冗談、脱線、言葉遊び |

**1回の会話で動く幅は小さい。** 一言で人格が変わってしまうと、
機嫌の悪い日が1日あるだけで別人になる。50回話してようやく形が見えてくる設計にしてある。

## 2. 会話 → 価値観8軸と覚え書き

**どこ**: `src/ai/reflection.ts` → `src/analysis/psychographics.ts`

6ターンごとに、直近のやり取りをまとめて読み直して2つを出す。

- **覚え書き**: 長く効く事実だけの箇条書き（「犬を飼っている」「夜勤」）
- **価値観**: Schwartz の価値観理論を8軸に簡約したもの
  （刺激・安定・他者配慮・達成・自律・主導・伝統・楽しさ）

推測を書かせないのが要点。「たぶん学生」が積み上がると、
分身が事実でないことを自信満々に喋るようになる。

## 3. 本人の申告で上書き

**どこ**: `src/persona/survey.ts`（会話の合間に1問ずつ聞く）

会話からの**推定**と、本人が**申告**した値は別々に持つ。
混ぜると、受け取った側が確からしさを判断できなくなる。
人格カードでは `owner.values`（推定込み）と `owner.declaredValues`（申告のみ）に分かれている。

## 4. 数値 → 身体（ここが肝）

**どこ**: `src/persona/avatarProfile.ts`

性格と価値観を、**身体を持ったときに何が違って見えるか**へ翻訳する。
数値をそのまま渡しても、ロボットもモデルも使えない。

### 4-1. 連続値 — 動きの質

| 出力 | どう決まるか | 効く場所 |
|---|---|---|
| `energy` | 陽気さ・刺激 | 動きの大きさと速さ |
| `gestureRate` | 陽気さ・ユーモア | 身振りの頻度 |
| `idleVariance` | 好奇心・慎重さの逆 | 待機中の揺らぎ。0だと置物 |
| `responseDelayMs` | **慎重さ**・安定 | 話しかけられてから動き出すまでの間 |
| `gazeHoldMs` | 温かさ・他者配慮 | 目線を合わせ続ける長さ |
| `postureOpenness` | 自立心・主導 | 姿勢の開き |
| `comfortableDistanceM` | 慎重さ・安定 | 近づいてよい距離 |
| `approachSpeedMps` | 主導・刺激 | 近づく速さ |
| `baselineSmile` / `blinkRatePerMin` | 温かさ・陽気さ | 表情の基準 |

**この表が翻訳のすべて。** 新しい機器を作るときは、この9個をその機器の
アクチュエータへ割り当てるだけでよく、人格の解釈をやり直す必要がない。

### 4-2. 離散値 — 判断の方針

際立っている価値観の軸だけを、**機械が分岐できる識別子**に落とす。
50付近（差が15未満）の軸は「特徴なし」として何も出さない——
全員に全部の方針が付くと、方針の意味が消える。

| 軸 | 高い | 低い |
|---|---|---|
| 刺激 | `prefer_novel_options` | `prefer_familiar_options` |
| 安定 | `confirm_before_change` | `tolerate_open_plans` |
| 他者配慮 | `notice_others_first` | `respect_distance` |
| 達成 | `track_progress` | `avoid_pushing_goals` |
| 自律 | `offer_choices_not_answers` | `give_one_clear_suggestion` |
| 主導 | `take_initiative` | `follow_the_lead` |
| 伝統 | `honor_routine` | `suggest_updates` |
| 楽しさ | `prioritize_enjoyment` | `stay_on_task` |

識別子は**訳さない**。日本語の説明（`behavior`）も一緒に持つが、
機器が分岐に使うのは識別子のほう。

## 5. 最小化

**どこ**: `tools/edge/compact.mjs`

数値と識別子だけの数百バイトに落とす。**会話も覚え書きも属性も入らない**
（渡す直前に機械で検査し、落ちたら配信しない）。

実測で1体あたり約250バイト（下の2体で 256 / 259 バイト）。
ESP32でも Raspberry Pi Pico でも載る。

## 6. 機器側 — イベントから動作へ

**どこ**: `tools/edge/rule_runtime.py`（参照実装。Arduino版・MicroPython版も同梱）

機器は状況を**イベント**として受け取り、数値と方針で分岐する。
**ここにLLMは登場しない。**

| イベント | 使う値 | 分岐の例 |
|---|---|---|
| 待機 | `idleVariance`, `energy`, `baselineSmile` | 揺れの幅と周期、表情の基準 |
| 人が近づく | `comfortableDistanceM`, `approachSpeedMps`, `confirm_before_change` | 自分から寄るか、待つか、下がるか |
| 話しかけられた | `responseDelayMs`, `gestureRate`, `gazeHoldMs` | 間の取り方、身振りの回数 |
| 予定が変わる | `confirm_before_change` / `prefer_novel_options` | 確かめるか、乗るか |
| 沈黙が続く | `take_initiative` / `follow_the_lead` | 自分から切り出すか、待つか |

### 実測（性格が逆の2体・同じファーム。2026-09-19 の実行）

```
                さきがけ        ひだまり
書き出しの大きさ  256バイト       259バイト
返すまでの間     458ms          890ms
身振り           2回            1回
待機の揺らぎ     ±10.2度        ±3.6度
心地よい距離     1.3m           1.4m
近づくか         自分から寄る    寄らない
```

> **この数字は実行のたびに少し動く。** 2体は `npm run persona:fixtures` が
> 毎回その場で作っており、性格の抽出をAIが行うため、同じ回答を入れても
> 数ポイントぶれる。**差の向き（さきがけのほうが速く、大きく動く）は変わらない**が、
> 「458ms」のような値をそのまま仕様として引用しないこと。

次の3コマンドで再現できる（`wrangler dev` を起動した状態で）。

```bash
npm run persona:fixtures
node tools/edge/make_compact.mjs tools/.persona-out/seeker.json -o bold.min.json
node tools/edge/make_compact.mjs tools/.persona-out/keeper.json -o careful.min.json
python3 tools/edge/rule_runtime.py bold.min.json careful.min.json --diff
```

## 7. 新しいロボットへ載せる手順

1. そのロボットで**変えられるもの**を洗い出す（速度・可動域・表情・発話・移動）
2. §4-1 の9個を、それぞれに割り当てる（0〜100 を実機の範囲へ線形に写すだけでよい）
3. §6 のイベントのうち、そのロボットに起きるものだけを実装する
4. **性格が逆の2体で動かして、差が目で分かるか**を確かめる（§6の表が基準）
5. 差が出ないなら、割り当てた範囲が狭すぎる。実機の可動域いっぱいまで使う

言葉が要る場面は、別建てで考える。

- ネットがある → `/api/chat`
- ネットが無くて、言葉が要る → Raspberry Pi 4 以上＋Ollama（`docs/EDGE_DEVICE_TEST.md`）
- 言葉が要らない → §6 だけで完結する

## 8. この作りの限界（先に書いておく）

- **観測が言葉だけ。** 実際に歩く速さや、声の大きさは測っていない。
  `energy` は「陽気な言い方をする人は、動きも大きいだろう」という**仮定**で、
  実機で確かめた対応づけではない
- **初期値は推測。** §4-1 の係数は設計時に置いたもので、実機を見ながら直す前提
- **会話が浅いと、ほぼ初期値。** 会話35回（おしゃべり期）未満の分身で比べても差は出にくい。
  判断プロファイル（`src/slm.ts`）が `confidence` を一緒に返すのはこのため
- **文化差を見ていない。** 対人距離は文化で大きく変わるが、いまは1つの値しか持っていない

これらは隠さずに相手へ伝えること。「言葉から動きが出ます」とだけ言うと、
実機で差が小さかったときに、仕組みごと疑われる。
