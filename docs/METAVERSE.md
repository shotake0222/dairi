# メタバース（/meta）

最終更新: 2026-09-23（NPC・会話・広告とランドマーク・和風10エリア・招待とWeb申し込みを追加）

わけたまで育った分身が、**人格の数値どおりに動く**共有の3D空間。スマホのブラウザで動く。
同じ部屋（エリア）にいる他の人の分身と会えて、置いた看板（広告）・動画・ミニゲームで遊べる。
ミニゲームは、歩いて遊ぶ3種と、**スマホのセンサー（ジャイロ・加速度・マイク・カメラ）とAR（WebXR）を使う20種**。

> 用語: 管理画面では「エリア」、コードと古い文書では「部屋（room）」。同じもの。

---

## 1. 入り方

- **キャラクター画面（/chat）の「🌐 メタバース」**から入る → `/meta?cid=<その子>`。
  その子にチェックが入った状態で部屋を選ぶ（この端末の他の子も、合わせて3体まで連れて行ける）
- 部屋のリンク `/meta?room=<id>` を配ることもできる（一覧に出していない部屋もリンクなら入れる）
- 部屋から「← 出る」で、来たキャラクター画面へ戻る
- **入る前に「はじめる前の同意」を確かめる。** 同意の版が上がった後まだ開いていない子は、ここで同意の画面が出る
  （入ってから断られるより先に済ませる）
- `/meta` は**アプリのホスト（app.waketama.com）だけ**で開く。`waketama.com/meta` はアプリのホストへ転送する
  （持ち主トークンはホストごとの localStorage にあるため。apex で開くと「この端末の分身」が見つからない）
- 連れて行けなかった子がいると、**理由ごとに直し方を出す**（下の「7. 困ったとき」。以前はすべて
  「この端末の分身だと確かめられませんでした」だった）

## 2. エリアの作り方（管理画面「メタバース管理」タブ）

**エリアは管理画面でだけ作る。** 利用者が作れるエリアは持たない
（見知らぬ人に任意の画像・文字を見せる口になるため。子どもも使う）。

| 設定 | 選べるもの |
|---|---|
| 場所 | 草原・おへや・境内・海辺・夜空の丘 |
| 時間帯 | 朝・昼・夕方・夜（空の色・光・星・ほたる・灯籠の明かりが変わる） |
| 最初の視点 | 見下ろし・正面・後ろから・この子の目線（入った人が画面で切り替えられる） |
| 状態 | 公開／準備中（管理者だけが入れる）／閉鎖 |
| 開放日時 | 任意。これより前は一覧に「近日開放」と出るが入れない。日時になると自動で入れる |
| 終了日時 | 任意。過ぎたら自動で閉鎖（キャンペーンの終わり） |
| 並び | 一覧の順番（小さいほど上） |
| 一覧に出す | 外すと、リンクを知っている人だけが入れる |
| 置く物 | 最大7つ。置き場所（奥・左奥・右奥・左・右・左手前・右手前）に1つずつ |

エリアの状態は、設定と日時から決まる（`areaState`）:

| 状態 | 一覧 | 入れる人 | 決まり方 |
|---|---|---|---|
| 公開中 open | 出る | だれでも | 状態＝公開、開放日時を過ぎている（または無い） |
| 近日開放 soon | 「近日開放 ◯月◯日」と出る | だれも入れない | 状態＝公開、開放日時より前 |
| 準備中 draft | 出ない | 管理者だけ（管理画面の Cookie） | 状態＝準備中 |
| 閉鎖 closed | 出ない | だれも入れない | 状態＝閉鎖、または終了日時を過ぎた |
| まとめ済み moved | 出ない | まとめた先へ案内 | 別のエリアにまとめた |

### 新しいエリアを開放する

1. 「＋ 新しいエリア」→ 状態は**準備中**で始まる。置く物を決めて保存
2. 一覧の「開く」で入って確かめる（準備中は管理者だけが入れる）
3. 状態を**公開**にし、開放日時を入れて保存 → それまでは「近日開放」、日時になると入れる
   （すぐ開けるなら開放日時は空のまま）

### エリアをまとめる（例: ひろばと夜空の丘を1つにする）

1. 「エリアをまとめる」で、まとめ先（残るエリア）を選び、まとめるエリアに印を付けて「まとめる内容を決める」
2. 置く物を合わせた下書きが開く。**置き場所が足りずに外した物は一覧で出る**ので、残したい物を置き直す
3. 名前などを直して保存 → まとめた元は `merged_into` にまとめ先が入る
   - まとめた元のリンク（`/meta?room=yozora`）で来た人は、まとめ先の設定で入る
   - まとめた元に**いま入っている人**には「エリアがひとつになりました」と出て、まとめ先へ移れる
4. やめるとき: まとめた元を「直す」→「まとめを解く」で保存。まとめ先を消した場合も、まとめは自動で解ける

### 最初からあるエリア

わけたまのひろば・夜空の丘はコードにある（`BUILTIN_ROOMS`）。**同じIDで保存すると、その設定で上書きされる**
（D1 に同じIDの行ができる）。一覧の「元に戻す」で行を消すと、最初の状態に戻る。「複製」で新しいエリアの元にもできる。

### 置く物

| 種類 | 中身 | 使いどころ |
|---|---|---|
| 看板 | 見出し・本文・画像（アップロードまたはURL）・リンク先・**広告として出す** | 広告・お知らせ。タップで詳しく、確認のうえ外部サイトへ |
| 動画 | 動画URL（音なし・くり返し） | 紹介動画・PV |
| いまいる子の紹介 | 部屋にいる子の名前と種族 | 待ち合わせ・にぎわいの見える化 |
| 宝さがし | 星の数（3〜30）・制限時間（15〜300秒）・クリアの言葉 | 回遊させたいエリア。クリアの言葉にクーポン案内を入れられる |
| ○×クイズ | 問題（10問まで。正解と一言つき）・全問正解の言葉 | 商品・企画の理解を深める |
| スタンプラリー | 旗の数（2〜8）・クリアの言葉 | 空間をひとまわりさせる |
| 📱 センサーのミニゲーム（20種） | 目標・制限時間・むずかしさ（1〜3）・クリアの言葉 | 下の表 |

- 保存すると、**いまエリアにいる人の画面もその場で変わる**（Durable Object から配り直す）
- 保存できない設定は理由つきで止まる（https でないURL、置き場所の重なり、問題の無いクイズ、終了日時が開放日時より前 など）

  断られても、画面の操作で遊べる
- **センサーの値・カメラの映像・声は、端末の中だけで使う。** 送らない・記録しない。マイクは大きさだけ、
  カメラは画面の背景に映すだけ。ゲームを終えるとマイク・カメラはすぐ止める（`sensors.mjs`）
- 本物のARは WebXR `immersive-ar`＋`hit-test` に対応した端末（Android の Chrome など）。iPhone の Safari は
  WebXR のARに対応していないので、カメラの映像の上で遊ぶ形になる
- ページのヘッダ `Permissions-Policy` で、傾き・動き・AR・カメラ・マイクを自分のページにだけ許している

## 2-2. ミニゲーム管理（管理画面「ミニゲーム管理」タブ）

| 操作 | 何が起きるか |
|---|---|
| 出す／止める | 止めると、置いたままでも**どのエリアにも出なくなる**（`meta_settings` の `games.disabled`）。いま開いているエリアからもすぐ消える。戻せばまた出る |
| 既定値 | エリアに新しく置くときの初期値（目標・秒・むずかしさ） |
| 使っているエリア | そのゲームを置いているエリアと状態 |
| 試す | そのゲームだけを置いた試し場 `r-game-test`（状態＝準備中。管理者だけが入れる・一覧に出ない）を開く |

### 看板・広告の画像

- 画像のある看板・広告・ランドマークは、タップすると詳細が開き、**画像を切り取らずに全体**を出す。画像をタップすると拡大表示
  （ピンチ・ダブルタップで最大6倍、ドラッグで移動。パソコンはホイール）。チラシの画像をそのまま載せても、細かい文字まで読める

### 広告のルール（必ず守る）

- **広告の看板には「広告」の札が自動で付く。外す設定は作っていない**（ステルスマーケティング規制。
  景品表示法の告示、2023年10月施行）。広告なのに「広告として出す」を外して出すのは禁止
- リンクは確認の画面を出してから、別のタブで開く（`noopener,noreferrer`。分身の情報は渡さない）
- 画像は「📷 画像を選ぶ」でアップロードできる（§2-6-1）。**URLを貼った画像と動画**は、相手のサーバーが外部からの読み込み（CORS）を
  許していないと表示されない。出ないときは、画像ならアップロードし直す（動画は自前の場所に置き直す）

## 2-4. NPC（運営の分身）— 管理画面「NPC・運営の分身」

- **管理者は上限なしで分身を作れる**（1回に50体まで・何回でも）。作った子は「この端末で育てる」で持ち主の印をその端末に置き、ふつうの会話で育てる
  - 育て方の手順・別の分身で育てた人格をファイルで入れる方法は [OPERATIONS.md](OPERATIONS.md) §5-3-2
  - 以前、管理者でも1日3体に当たることがあった: 管理者の印（Cookie）が `waketama.com` にだけ付き、本体（app）で管理者と分からなかったため。
    いまは本番の2つのホストで共有する（`Domain=waketama.com`。`src/admin.ts` の `adminCookieDomain`）
- **NPC にできるのは運営の分身だけ**（`admin_characters` に載っている子）。利用者の分身は置けない
- NPC はエリアごとに12体まで。位置（真ん中・左右・手前・奥…）・歩き回る広さ・役目（名札）・ひとこと・リンク・広告にするか・話しかけられたら答えるか
- 動きは利用者の分身と同じエンジン（性格の数値）。散歩の行き先は「時刻とNPCの番号」から各端末が同じ計算をする（サーバーは位置を配らない）
- 自分の子が近づくと、NPC が決まった台詞かひとことで声をかける。タップで詳細、「話しかける」で会話
- 姿と性格の写しは D1（`meta_npcs.avatar`）に持ち、6時間ごとに取り直す。「すべて最新の性格にする」ですぐ反映
- 分身の識別子（cid）は部屋の中だけで使い、画面にも電文にも出さない

## 2-5. メタバースでの会話（吹き出しで、文字・声・視線）

「💬 話す」で、話す子の頭の上に吹き出しが出る。入力は3通り: **文字**・**声**（端末の音声認識）・**視線**（6つの言葉から見つめて選ぶ。
カメラが使えないときは、枠が順に光るスイッチ操作）。

| 相手 | 何が起きるか | 他の人に見えるもの |
|---|---|---|
| 自分の子（相手を選ばない） | ふだんの会話（`/api/chat`）。**育つ** | 「…」だけ（返事は自分の画面にだけ。覚えていることを人前で言わないため） |
| ほかの子・NPC（タップで選ぶ） | 入力した「伝えたいこと」を手がかりに、**自分の子が自分の言葉で**話しかけ、相手の子が返事をする（`metaTalk`） | 分身の言葉だけ。**入力した文字そのものは配らない** |

- 分身の言葉は、よその分身と話すための指示（`buildMeetingPrompt`。会話・記憶を使わない）で作り、URL・メール・電話番号らしきもの・不適切な語を機械的に落とす（`src/metaText.ts`）
- 話したこと・聞いたことは、双方の分身の「出会いの記録」と性格に少しだけ残る（育つきっかけ）
- 回数の制限: 1人あたり5秒に1回・1回の入室で80回まで（AIを使うため）

### 自動と手動（HUD の「🤖 自動／✋ 手動」）

| モード | 動き | 会話 |
|---|---|---|
| ✋ 手動（既定） | 自分でタップして歩かせる | 吹き出しに入力して話す |
| 🤖 自動 | 育った人格のとおりに自分から歩く（人なつっこい子ほど近くの子へ、好奇心の強い子ほど屋台や看板へ、元気な子ほどよく動く） | 近くの子・NPC に**自分から話題を選んで**話しかけ、2往復話す（話しかける間は人なつっこさで20〜60秒、同じ相手には2分あける） |

- 自動のときに地面をタップすると、15秒だけ手動で動かせる。吹き出しからの会話も使える
- 自動のときはミニゲームの案内を出さない（勝手に始めない）
- サーバー側でも、自動の会話は15秒に1回まで（`AUTO_TALK_INTERVAL_MS`）。1回の入室で80回を超えると、歩くだけになる

### 交流の記録（「お散歩」の図鑑とひとつに）

メタバースでの会話は、「お散歩」と同じ**交流の記録（出会いの図鑑 `/friends`）**に積む。HUD の「📖 記録」から開ける。

- 記録には、どこで会ったか（🌐 メタバース・エリア名／🚶 お散歩）、運営の分身か、何回会ったかが付く。「メタバース／お散歩」で絞り込める
- 同じ相手との続きの会話（15分以内）は1件にまとめる
- **お散歩で会った子とメタバースで会っても「また会えた」と数える**（相手の識別子のハッシュ `partnerKeyOf` を両方で使う）。
  再会すると「◯回目の出会い」と知らせ、分身は前に聞いた言葉を覚えて話しかける
- 相手の仮の印は、画面へ渡すときに持ち主ごとに別の値へ変える（別の子の記録と突き合わせて、同じ相手を追えないように）

## 2-6. 広告・クーポン・デジタルランドマーク — 管理画面「広告・ランドマーク」

**広告の詳細**: 看板（エリアの置く物）や区画の広告をタップすると、詳細が開く（画像・説明・提供者・**QRコード**・**リンク**・**特別クーポン**）。
クーポンは「クーポンを表示」を押すとコードが出る（コピーできる。期限を過ぎると押せない）。QRコードは「QRの行き先」、無ければリンク先を指す。

**区画**: どのエリアにも外周に8つの区画（`LAND_SPOTS`）がある。区画ごとに「売る物（広告／ランドマーク）」と価格（1単位）を決める。

**流れ**（決済はこのサービスの外。カード番号などは預からない）:

1. 申し込み（`/land`）: 区画・中身（看板の文字・画像・リンク・QR・クーポン、またはランドマークの形8種×色6種・銘板）・連絡先
2. 管理画面で中身を確かめ「承認」→ 金額と決済リンク（Stripe の Payment Link・請求書のURLなど）を入れる → 申込者の状況ページに出る
3. 入金を確かめたら「支払い済み」→ その日から期間ぶん表示（重なる期間があれば止まる）
4. 期間が過ぎると自動で消える。取り消し・いますぐ終える・消すも管理画面から

- **中身は必ず運営が見てから出す**（自動では掲載しない）。広告には「広告」、ランドマークには「提供: ○○」

**管理画面の並び**（2026-09-24 に整理。上に「A. 運営が自分で置く／B. 広告主から申し込んでもらう」の案内がある）:

| タブ | やること |
|---|---|
| ① いま出ている広告 | 区画の広告・ランドマークと、エリアの看板で「広告として出す」にした物の一覧。直近30日の「詳細を開いた」「リンクを開いた」「クーポンを表示」の回数（誰が見たかは持たない） |
| ② 運営が置く | 申込なし・無料で区画に置く。**右にプレビュー**（メタバースと同じ部品で描いた見え方＋タップしたときの詳細）。エリアの見取り図で区画を選べ、使用中の区画が分かる。「メタバースで確かめる」で実際のエリアを開く |
| ③ 広告主からの申込 | `/land` から届いた申込。中身を詳細のプレビューで確かめ、画面の中で承認（金額・決済リンク）→ 支払い済み（表示開始）／見送り。「この中身で見え方を確かめる」で②に写して3Dで見られる |
| ④ 申込ページの設定 | 「受付」＝**外部の広告主が `/land` から申し込めるようにするか**。単位の日数・決済リンクの既定値・支払いの案内、空き区画に「広告 募集中」の目印を出すか。区画ごとの「申込で出す物」と価格（見取り図つき） |

- エリアの**内側**（真ん中を囲む7か所）の看板は「メタバース管理」の置く物で置く（「広告として出す」にチェック）。ここで扱うのは**外周**の区画
- 申込者の連絡先は、掲載が終わって1年たつと自動で消す

### 2-6-1. 画像のアップロード（`src/media.ts`・`public/image-upload.js`・migration 0016）

| 口 | 使う画面 | 決まり |
|---|---|---|
| `POST /api/admin/media` | 「② 運営が置く」・メタバース管理の看板 | 合言葉の内側 |
| `POST /api/land/image` | 申込ページ `/land` | 受付がオンのときだけ。同じ送信元から1日12枚（`LAND_IMAGE_DAILY_LIMIT`） |
| `GET /img/<id>.<拡張子>` | メタバース・詳細画面・プレビュー | 同じサイトから配る（CORS の心配なし）。中身は変わらないので1年キャッシュ |

- 端末で長い辺1600pxに縮め、WebP（描けない端末は JPEG）にしてから送る。描き直すので写真の位置情報（Exif）は落ちる
- サーバーは大きさ（1.5MBまで）と先頭の数バイト（WebP・JPEG・PNG）で確かめて D1 の `meta_images` に入れる。SVG・GIF は受け取らない
  （SVG はスクリプトを含められるため）。配るときは `content-security-policy: default-src 'none'; sandbox` を付ける
- 保存する中身には `/img/…` の相対パスが入る（`cleanImageUrl`。https:// と同じ扱い）。本体とLPのどちらのホストでも同じ画像が出る
- 申込ページから入れて、どの申込・掲載にも使われない画像は30日で消す（Cron。`purgeUnusedImages`）。管理画面から入れた画像は消さない
- 誰が送ったかは持たない（回数は日ごとに塩を変えたハッシュで数える。`src/lib/ipQuota.ts`）

## 2-7. 依代（NFC）を使わない入口 — 管理画面「招待・申し込み」

| 入口 | 使いどころ | 流れ |
|---|---|---|
| 招待リンク `/i/<コード>` | イベント・キャンペーン・法人の配布・メールやSNS | 管理画面で発行（1回だけ／N回まで・期限つき・まとめて何本でも）→ 開いた端末に新しい分身と持ち主の印 |
| Web申し込み `/apply` | 依代を持たない人の申し込み | 申し込み → 管理画面で承認 → 申込者の状況ページに「分身をはじめる」（1回だけの招待リンク）。自動承認にもできる（1回線1日3件） |
| 引き渡しリンク | 運営が育てた分身（人格データ）を渡す | 運営の分身から発行 → 開いた端末が持ち主になり、運営の一覧から外れる（1回だけ） |
| これまでの入口 | | `/t`（かざす）・`/q`（QR）・`/w`（リンクだけ。`ENTRY_OPEN` のとき） |

- どの入口も、持ち主の印（トークン）は `/summon` へのURLで一度だけ渡し、画面がすぐ端末に保存してURLから消す（`/t` と同じ）
- 使えない招待リンク（使い切り・期限切れ・停止中）は `/apply?invite=…` で理由を伝える
- メールは自動で送らない。連絡先へは運営から知らせるか、申込者が状況ページで受け取る

## 2-8. 通貨・お店・提携店の引換券 — 管理画面「通貨・お店」

メタバースの中だけで使えるポイント（既定の名前「たまコイン」。名前・単位・記号は変えられる）と、それを使うお店、
リアルの提携店で使える引換券（`src/economy.ts` ／ 画面は `public/meta/wallet.mjs`・`/redeem`）。

### 通貨の約束（崩すと法律上の扱いが変わる）

| 約束 | 理由 |
|---|---|
| **お金で売らない** | お金で売ると「前払式支払手段」（資金決済法）。提携店でも使えるなら**第三者型として登録が必要**（発行保証金の供託など）。いまは「遊ぶと貯まる」だけなので、その扱いにならない |
| **お金に戻さない・換金しない** | 払い戻し・現金化は資金移動業・暗号資産の論点になる。口を作っていない |
| **利用者どうしで渡せない** | 見知らぬ人・子どもどうしの「ちょうだい」の口にしない。サービス外の売買（RMT）も防ぐ |
| リアルでは**提携店の引換券**にかえる | 特典（割引・1品無料など）は提携店が出す。景品表示法の景品の上限（総付景品なら取引価額1,000円未満は200円まで、1,000円以上は2割まで）に収まるよう、提携店と決める |

> 将来お金で売りたくなったら、この表の前提が変わる。**実装より先に弁護士・資金決済法の専門家に相談する**こと。

### 貯まり方（管理画面で変えられる）

| 理由 | 既定 | 決まり |
|---|---|---|
| 毎日の入室 | +10 | 分身ごと1日1回（部屋＝サーバーが入室を確かめる） |
| ミニゲームのクリア | +5 | 同じエリアの同じ屋台は1日1回。端末から「クリアした」ことだけを送る（点数は送らない）。部屋が「その屋台が本当にこの部屋のゲームか」を確かめる。8秒に1回まで。試し場では貯まらない |
| 分身どうしのおしゃべり | +2 | 話しかけた側だけ。1日10回まで |
| 運営の付与・回収 | 任意 | 理由が必須。出入りの記録と利用者の財布に「運営: 理由」と出る。1日の上限の外 |

- 遊んで貯まる額は **1日150まで**（日本時間の日付で区切る）。残高の上限は 99,999
- クリアの判定は端末なので、ずるはできる。だから**1回の額を小さく・1日の上限を必ず付ける**。引換券の枚数にも上限（1体1か月3枚）を付けて、リアルの価値へ流れる量を絞っている

### お店と商品

- 商品の種類: **身につける物**（18の形: リボン・お花・はっぱ・星・麦わら帽子・シルクハット・王冠・天使の輪・ねこみみ・うさみみ・ベレー帽・キャップ・
  魔女の帽子・サンタ帽・おにのつの・桜のかんざし・ヘッドホン・まるメガネ。色も選べる。メガネだけは顔の前に掛ける）／
  **演出**（花火・ハート・紙ふぶき・シャボン玉・桜ふぶき・星のシャワー・雪・音符。使うと1つ減り、部屋のみんなに見える）／**リアル引換券**（提携店・有効日数・1体1か月の数・店頭での使い方）
- 最初からある商品は **42点**（2026-09-24 に30点追加。`BUILTIN_ITEMS`）。どれも管理画面で値段・在庫・販売の有無を直せる
- 最初からあるお店: ひろばの雑貨屋（ひろば）・わけたま引き換え所（ひろば。商品は提携店を足してから）・お祭りの花火屋（夏祭り・ゆうえんち）・おかしの国の帽子屋（おかしの国）・
  桜の神社の和小物屋（桜の神社）・ゆうえんちのファンシーショップ（ゆうえんち）・雪の里のおみやげ屋（雪の里）
- エリアに置くには「メタバース管理」の置く物で「お店」を選び、どのお店かを選ぶ。屋台の前の輪に入るかタップで開く。
  **HUD の「🛍 お店」からも開ける**（縦長の画面では、左右の置き場所の屋台が画面の外になりやすいため。お店のあるエリアでだけ出る）
- 在庫を決めると、売り切れたら買えない。残高は「足りるときだけ引く」1文の更新なので、同時に押しても負にならない
- 身につけている物は入室のときに部屋が読み、付け替えたら部屋のみんなに配る（`wear`）。演出は部屋が持ち物から1つ減らしてから配る（`effect`）

### 提携店と引換券（リアルで使う）

1. 「提携店」を足す → **お店の暗証番号（8けた）を1回だけ表示**（保存しないので、なくしたら「作り直す」）。安全な方法でお店に伝える
2. 「商品」でリアル引換券を作り（提携店・有効日数・1体1か月の数・使い方）、「お店」（引き換え所）に並べる
3. 「通貨の設定」で **「提携店の引換券への引き換えを受け付ける」** をオンにする（既定はオフ）
4. 利用者は引き換え所で引換券にかえる → 財布の「引換券」に番号（10けた）とQRが出る
5. お店の人は **`/redeem`** を開き（QRを読むと番号が入る）、暗証番号を入れて「確かめる」→「使ったにする」
   - ほかの店の暗証番号では「見つからない」と同じ返事になる（どの店の券かも分からない）
   - 確認画面に出るのは、引換券の名前・期限・使ったかどうかだけ。利用者の名前・分身の情報は出ない
   - まちがいは1回線1日30回まで
6. 「引換券」の一覧で、提携店ごとの枚数を見て精算する。未使用の券は「取り消して返金」できる（使用済みは取り消せない）

## 3. 仕組み

```
管理画面 ──保存──▶ D1 meta_rooms（設定だけ。objects は JSON。状態・開放/終了日時・まとめ先・並び）
                    D1 meta_settings（games: 止めたミニゲーム・既定値）
                         │
/meta ──GET /api/meta/rooms──▶ 部屋の一覧と選択肢の定義（metaverseCatalog）
   │
   └──WebSocket /api/meta/rooms/:id/ws ──▶ MetaverseRoom（Durable Object・1部屋1つ）
          join（cid＋持ち主トークン）→ CharacterState.getMetaverseAvatar で本人確認
          ◀ welcome（部屋の全員の「姿と動きの数値」）
          move / stamp / greet を中継（本人の分だけ・回数制限つき）
          ◀ config（管理画面で保存したとき）／ moved（まとめた）／ closed（閉じた・準備中に戻した）
```

- 入室の口（WebSocket）は、公開中のエリアだけ受ける（準備中は管理者だけ）。近日開放・閉鎖は 409 と状態、
  まとめ済みは 409 と `movedTo` を返す
- 断った子は理由の種類を返す（`no_token` / `not_owner` / `no_consent` / `not_found` / `already_here` / `unavailable` /
  `audit_failed`）。全員だめなら `{t:"error", code:"join_failed", rejected}`、一部だけなら入った上で `welcome.notices`

- **分身の動きは各端末が計算する。** サーバーが配るのは約250バイトの最小形（compact）で、
  それを実機の検証機と同じ振る舞いエンジン（`public/meta/wt_core.mjs` ＝ `tools/device/web/wt_core.mjs` の写し）
  に通す。近づく・待つ・下がる、返すまでの間、手を振る回数が、その子の性格どおりに分かれる
- 3Dモデルは `public/characters/*.glb`。three.js の GLTFLoader は使わず、頂点色だけの形を読む小さな読み込み器
  （`public/meta/glb.mjs`）で読む。three.js 本体は `public/vendor/three.module.min.js`（CDNに頼らない）
- 声は分身ごとの声（`src/ai/voiceProfile.ts`）。高音質（MeloTTS）を選んでいれば、再生速度で声を分ける
- WebSocket Hibernation を使うので、人がいても静かな間は Durable Object が眠れる

## 4. 他の人に渡るもの・渡らないもの

| 渡る（同じ部屋の人の画面） | 渡らない |
|---|---|
| 名前・種族・色・声の高さと速さ・動きの数値・位置・スタンプ・挨拶（決まった台詞の番号） | 会話・覚え書き・記憶・属性・分身の識別子・持ち主トークン・利用者が書いた文字 |

- 入退室・移動・ミニゲームの結果は**記録しない**（Durable Object のメモリにだけあり、出れば消える）
- ミニゲームはその端末の中だけで遊ぶ。自己ベストだけ localStorage（`sodatsukake_metaBest_*`）に残す
- センサー（傾き・動き）・マイクの大きさ・カメラの映像は、端末の中でゲームに使うだけ。サーバーへは何も送らない
- 挨拶は `GREETING_LINES`、スタンプは `STAMPS` から選ぶだけ。**利用者どうしの自由な文字のやりとりは作らない**

## 5. 上限

| 項目 | 値 | 場所 |
|---|---|---|
| 1部屋の人数 | 12端末 | `MAX_PEOPLE` |
| 1端末が連れて行ける分身 | 3体 | `MAX_ACTORS_PER_PERSON` |
| 移動の送信 | 1秒に8回まで | `MOVES_PER_SECOND` |
| スタンプ／挨拶 | 0.7秒／2.5秒に1回 | `STAMP_INTERVAL_MS` / `GREET_INTERVAL_MS` |
| 空間の広さ | 中心から ±9m | `WORLD_HALF` |

## 6. 出すときの手順

1. `npm run db:migrate:remote`（`0012_metaverse.sql`・`0013_metaverse_areas.sql`・`0014_npc_land_invites.sql`。**デプロイより先**）
2. `npm run deploy`（`wrangler.toml` の Durable Object マイグレーション `v2` で `MetaverseRoom` が作られる。タグは変えない・消さない）
3. 管理画面「メタバース管理」タブでエリアを作り、「開く」で確かめる
4. スマホ実機で、2台同時に同じエリアへ入り、互いの子が見えて動くこと・挨拶の声が出ることを確かめる
5. 「ミニゲーム管理」の「試す」で、センサーのゲームを iPhone（許可のダイアログ）と Android（ARでおでかけ）で1回ずつ遊ぶ

## 7. 困ったとき

入れなかったときの画面の文言と、直し方:

| 画面の文言（理由） | 原因 | 直し方 |
|---|---|---|
| 「持ち主だと確かめられませんでした」（not_owner） | 別の端末で育てた子、またはこの端末の持ち主の印が古い | もとの端末の「📦 保存/復元」で引き継ぎコードを出し、この端末で戻す |
| 「持ち主の印が、この端末にありません」（no_token） | ブラウザのデータ削除・機種変更 | 引き継ぎコードで戻す |
| 「はじめる前の同意が済んでいません」（no_consent） | 同意の版が上がった後、まだ開いていない | 「キャラクター画面を開く」→同意（入る前にも同意の画面を出すようにした） |
| 「見つかりませんでした」（not_found） | 消した子 | 端末の一覧から外す |
| 「もうこの部屋にいます」（already_here） | 別のタブ・端末で同じ子が入っている | そちらを閉じる |
| 「このエリアはまだ開いていません」 | 開放日時の前 | 日時を待つ（管理者は開放日時を見直す） |
| 「このエリアは準備中です」 | 状態が準備中 | 管理者だけが入れる。公開にする |
| 「エリアがひとつになりました」 | まとめた | まとめた先へ移る |

その他:

| 症状 | 見るところ |
|---|---|
| `waketama.com/meta` で子が出ない | アプリのホスト（app.waketama.com）へ転送されているか。ホストごとに持ち主の印が別 |
| 画面が真っ黒 | 端末・ブラウザが WebGL を切っている（「この端末では表示できません」が出る） |
| 看板の画像・動画が出ない | URLを貼った物なら CORS。画像は「📷 画像を選ぶ」でアップロードし直す。アップロードした画像が出ないなら migration 0016 が本番に当たっているか |
| 設定を変えたのに変わらない | 保存したか（管理画面に「保存しました」）。入り直すと必ず新しい設定になる |
| 満員と出る | 12端末まで。エリアを分ける（「複製」） |
| センサーのゲームが画面の操作になる | iPhone で「動きと向き」を許可しなかった。設定 → Safari → 「モーションと画面の向きのアクセス」、またはページを開き直して許可 |
| マイク・カメラのゲームが始まらない | ブラウザのサイト設定でマイク・カメラが拒否になっている |
| 「ARでおでかけ」がカメラの映像になる | その端末・ブラウザが WebXR のARに非対応（iPhone は非対応。Android は Chrome と「Google Play 開発者サービス（AR）」が要る） |
| ミニゲームが出ない | 「ミニゲーム管理」で止めていないか |
