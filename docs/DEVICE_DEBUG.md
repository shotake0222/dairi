# 実機デバッグ手順書

対象読者: 開発者（コードを直す人）。運用担当者向けの「よくある障害の切り分け」は
[OPERATIONS.md](OPERATIONS.md) の「6. 障害のときの切り分け」を見てください。こちらは
「NFC・カメラ・マイク・PWAインストールは、PCのブラウザでは確認できない」という前提のもとで、
**実機のブラウザに出ているエラーを、PCの画面から見る**ための手順です（ROADMAP §0-5）。

最終更新: 2026-09-21

---

## 0. なぜこれが要るのか

`/talk`（NFCで話す）、カメラを使う機能、PWAのホーム画面インストールは、
どれも「実機でしか再現しないバグ」の温床です。PCのChromeでどれだけ検証しても、

- iPhoneのSafariだけ挙動が違う（`SpeechRecognition` の対応状況など）
- Android実機だけ、通知の許可ダイアログが出るタイミングが違う
- 「読み取れない」と言われたが、そもそもNFCタグに何が書き込まれているか分からない

といった問題は再現できません。実機の開発者コンソールをPCから覗く方法と、
検証用NFCタグの作り方をここにまとめておきます。

---

## 1. iPhone: Mac の Safari から実機に接続する

必要なもの: Mac、iPhone、Lightning/USB-Cケーブル（初回はUSB接続を推奨。Wi-Fi経由も後述の設定で可能）。

1. **iPhone側**: 設定 →「Safari」→ 一番下の「詳細」→「Webインスペクタ」をオンにする。
2. **Mac側**: Safari を開き、メニューバー →「Safari」→「設定」→「詳細」タブ→
   「メニューバーに"開発"メニューを表示」にチェック（Safari 17以降は「機能拡張」設定内の場合あり。
   見当たらなければ Safari のバージョンに応じて設定内を探す）。
3. iPhoneとMacをケーブルで繋ぐ（初回は iPhone 側に「このコンピュータを信頼しますか」が出るので許可）。
4. iPhoneで `https://waketama.com`（または対象のURL）を開く。
5. Mac の Safari →「開発」メニュー → 接続した iPhone の名前 → 開いているタブ名（`waketama.com` など）をクリック。
   → Mac側にWeb Inspectorウィンドウが開き、実機のDOM・コンソール・ネットワークタブがそのまま見える。
6. コンソールに `console.log` を仕込んだコードを実機で動かせば、Mac側にリアルタイムでログが出る。
   ブレークポイントも打てるので、ステップ実行も可能。

**Wi-Fi経由にしたい場合**: 一度USBで接続してWebインスペクタを使った実績があれば、
「開発」メニューの中に対象のiPhoneがWi-Fi経由でも出てくることがある（iOS/macOSのバージョン依存）。
出ない場合はケーブル接続に戻す。

**ハマりどころ**:
- 「開発」メニューにiPhoneが出ない → iPhone側のロックを解除した状態にする、
  ケーブルを挿し直す、iPhone側の「信頼する」ダイアログを見逃していないか確認する。
- Web Inspector上のコンソールでは動くのに実機の見た目では動かない、という体感があれば、
  それはたいてい「実機は仕様通りだが、期待している挙動が違う」ケース
  （後述 3. の `getUserMedia` / `SpeechRecognition` の制約など）。

## 2. Android: Chrome の `chrome://inspect` から実機を開く

必要なもの: PC（Windows/Mac/Linuxいずれも可）、Android実機、USBケーブル。

1. **Android側**: 設定 →「デバイス情報」→「ビルド番号」を7回連続タップ →
   開発者向けオプションが有効になる。設定 →「開発者向けオプション」→「USBデバッグ」をオン。
2. USBケーブルでPCと接続。Android側に「USBデバッグを許可しますか」ダイアログが出たら許可
   （「このパソコンを常に許可する」にチェックしておくと以後スキップできる）。
3. PCのChromeで `chrome://inspect#devices` を開く。
   → 接続した端末名と、その端末で開いているタブの一覧が出る。
4. 対象のタブの下の「inspect」リンクをクリック
   → PC側にDevToolsが開き、実機のDOM・コンソール・ネットワーク・パフォーマンスタブがそのまま使える。

**ハマりどころ**:
- 端末が一覧に出ない → USBケーブルを「データ転送対応」のものに変える（充電専用ケーブルだと出ない）、
  `chrome://inspect#devices` の「Discover USB devices」にチェックが入っているか確認する。
- 会社支給端末などでUSBデバッグ自体がMDM（モバイル端末管理）でブロックされていることもある。

## 3. カメラ・マイク・通知など、権限まわりの実機特有の挙動

PCのブラウザと実機で挙動が変わりやすいポイント。バグだと思ったら先にここを疑う。

- **iOS Safari は、ユーザー操作（タップ）の直後でないと音声再生・録音を開始できない**。
  `/talk` の音声再生がボタン経由でしか鳴らないのはこの制約に合わせた設計（既存実装済み）。
  「タップなしで自動再生できない」はiOS Safariの仕様であって、実装のバグではない。
- **`SpeechRecognition`（音声認識）は iOS Safari では長らく未実装/制限あり**。実機で動作確認する際、
  「Androidでは動くのにiPhoneで動かない」が出たら、まずiOS Safariのサポート状況を疑う
  （Web Inspectorのコンソールで `window.SpeechRecognition` / `window.webkitSpeechRecognition` の有無を確認）。
- **カメラ・マイクの権限はドメイン単位で記憶される**。一度「拒否」を選ぶと、
  実機のブラウザ設定（iOSなら設定アプリの「Safari」→「Webサイトの設定」、
  Androidなら Chrome のサイト設定）から手動でリセットしないと再度聞かれない。
  「もう一度権限ダイアログを出したい」ときはここを疑う。
- **通知許可**は、PWAとしてホーム画面に追加したあとと、ブラウザタブのままとで挙動が変わる端末がある。
  切り分けるときは「ブラウザタブで再現するか」「ホーム画面アイコンからの起動でも再現するか」の両方を試す。

## 4. PWA（ホーム画面インストール）の確認

- **iOS**: Safariで対象URLを開く → 共有ボタン →「ホーム画面に追加」。
  Service Workerの更新が反映されないときは、ホーム画面アイコンを一度削除して再追加するのが最も確実
  （iOSはPWAのキャッシュ周りの挙動がAndroidより保守的）。
- **Android**: Chromeで対象URLを開く → アドレスバー付近に出るインストールバナー、
  またはメニュー →「アプリをインストール」。
- 更新確認は `/api/health` のレスポンスヘッダに載っているデプロイのバージョン（コミットハッシュ等、§0-3）を、
  実機のWeb Inspector / DevTools の Network タブで見るのが早い。
  「直したはずなのに直っていない」の9割は、実機に古いバージョンがキャッシュされている。

## 5. NFCタグの書き込み・検証

検証用のタグに、実際にサービスが読むURL（`/t/<code>` など）を書き込む手順。

- **iPhone**: 「NFC TagWriter by NXP」（App Store）。
  タグを選択 →「その他」→「URL/URI レコード」→ 対象のURLを入力 → 書き込み。
  書き込み後は同じアプリの「タグを読む」機能、または実際にiPhoneのカメラを起動していない状態で
  タグにかざして通知バナーが出るかで確認する。
- **Android**: 「NFC Tools」（Google Play）。
  「書く」タブ →「レコードを追加」→「URL/URI」→ URLを入力 →「タグに書き込む」。
  同アプリの「読む」タブでタグの中身（URL・タグの種類・容量）を確認できる。
- **検証時の注意**:
  - 空のNTAG213/215/216タグはUIDがランダムなことが多いが、稀に**同一UIDのフィラー品**が混じる
    ロットがある。`?u=` のUIDミラーを使う検証では、複数タグのUIDが本当にバラけているか
    NFC ToolsやNFC TagWriterの「タグ情報」画面で確認してから使うこと
    （`src/yorishiro.ts` の `suspectedFiller` 判定はこれの対策）。
  - `/t/<code>` 方式で使う場合、コードは `tools/`（タグ発行スクリプト）で生成したものを使うのが正しいが、
    手元での動作確認だけなら任意の未使用コードでもよい（未登録コードでも新規の依代として受け付ける仕様。
    ただし同一回線からの連続受け付けには上限があるので、大量の検証タグを一気に試すとブロックされる場合がある。
    `src/yorishiro.ts` の `TAG_CLAIM_DAILY_LIMIT` を参照）。

## 6. うまくいかないときの一次切り分けフロー

1. まずPCのブラウザで同じ操作を再現できるか試す → 再現するならこの文書は関係ない、通常のデバッグへ。
2. 実機だけで再現するなら、1節・2節の手順でWeb Inspector / DevToolsを繋いでコンソールとネットワークタブを見る。
3. エラーが出ていない（＝JSは正常に動いているのに見た目がおかしい）場合は、3節の「権限・iOS特有の制約」を疑う。
4. 「動いていたはずなのに急に壊れた」なら、まずデプロイのバージョン（4節）とService Workerのキャッシュを疑う
   （OPERATIONS.md §6-3「Service Worker が壊れた」も参照）。
